# M7.9 — Case Board: spine, list, pane

The visibility milestone. Goal: the board stops being seven equal-weight tables and becomes the advisor's working screen — which car needs me, what do I do next, oldest first — while the manager still reads the whole yard and its money at a glance. Decided in the 2026-09-10 board design session (drafts compared by eye: two-lane queue, stage columns, flat sheet, then the ClaimTrack-organized list with a spine strip); rulings **D-26 – D-28** in DESIGN.md. No schema changes. One derivation extension, one deep link, one new client surface.

**Branch:** `m7-9-case-board` · **Gate:** on the staged shop, the advisor reads the top row and knows their next move without opening a case; every open case still appears exactly once; both languages read naturally.

## Scope (in)
1. **Board facts per case** — the query gains what `nextActionFor` needs (finding counts, unpriced Proposed lines, quotation coverage via `offerNeedsSending`, last quotation send date) and what the rows show (technicians, part progress, balances). A pure `lib/board.ts` turns a case into a serializable row DTO: stage, next action, pill (kind + params), age days and tone, money line. Unit-tested.
2. **Spine strip** — five segments with count, key number, oldest wait; lit when the stage needs a human; tap filters the list (client state, no URL change). Balance-due segment hides when empty, as before.
3. **List** — Needs me / All switch (default Needs me), plate/name/reference search, D-2 group dividers with money lines, rows per D-26, age tones. Empty states: nothing open (existing copy), nothing needing me, no search match.
4. **Pane** — selected case (first row by default): walkaround photo or body icon, plate, stage pill, next step / key date / contact, the stage spine, Offer or Work ledger, Done receipt line, primary next action + Open case. Actions deep-link the case page with `?action=` so the dialog opens on arrival; Open inspection links the inspection screen; Record QC / payment anchor as the case page does.
5. **Deep link** — the case page accepts `?action=<StageAction>` and asks the Jobs flow for it once on mount.
6. **Brand marks** — `BrandMark` renders a self-hosted SVG for known makes from `public/brands/`, else a two-letter monogram. Ships with the monogram path and an empty set; logos are assets the founder supplies.
7. **Skin** — the board is built in D-27's language with local utilities (`lift`, pill classes); no shared component changes, so other screens are untouched until the restyle milestone.
8. **Copy** — every new string in both message files.

- Logo in the list circle, real photo in the pane (D-28).
